# PR #1379 CI Build Check Plan

## Goal

Make the committed Web Cockpit bundles reproduce in GitHub Actions so PR #1379 passes `Web Unit`'s generated-artifact check.

## Scope and non-goals

- Scope: Web build configuration, build-check script, locked frontend tooling, and generated `app.js` / `terminal.js` artifacts if needed.
- Non-goals: changing session-expiry behavior, unrelated Web UI changes, or altering CI policy.
- Approval: granted for the bundle regeneration, test fix, and push to PR #1379.
- Diagnosis: CI runs locked Vite 8.3.0; the worktree had Vite 8.3.5 installed when the merge bundle was generated. `npm ci` followed by Vite 8.3.0 rebuild reproduced a passing `web:build:check` and regenerated only `app.js` and `terminal.js`.
- Second CI failure: after the network-retry fix (commit c87668e8, generic fetch rejections are retryable `network` failures that must not trigger session-expiry navigation), the stale expectation in `crates/ajax-web/web/src/features/settings/diagnostics.test.ts` ("uses shared session-expiry recovery when a protected route fails") still asserted `location.replace` navigation on a rejected protected fetch and failed the Web Unit job.

## Architecture

- Build source: `crates/ajax-web/web/src/`.
- Generated assets: `crates/ajax-web/web/dist/` are committed and checked for reproducibility by `scripts/web-build-check.mjs` plus `git diff --exit-code crates/ajax-web/web/dist`.
- Preserve the existing source/artifact contract and locked dependency versions unless the diagnosis proves a minimal tooling/config adjustment is needed.
