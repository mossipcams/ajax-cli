## Correctness findings

**BUG B1 — Idle cancellation breaks context reset, harness switching, and forced replacement.** `release_live_client` calls `client.cancel()?` whenever the host is alive, even when there is no active prompt (`slices/task_session_spawn.rs:343`). Both RPC variants forward their clients’ idle-cancel error (`session_client.rs:264`; `rpc_client.rs:99`); that behavior is explicitly locked by `rpc_session_tests.rs:153`, `pi_rpc_client_tests.rs:148`, and `session_client_claude_tests.rs:165`. Thus `clear_session_context`/`reset_harness_context` returns before teardown or new spawn for an idle live RPC session (`slices/task_session_spawn.rs:208`, `:262`). ACP’s cancel command sends a notification without requiring an active prompt (`sdk_connection.rs:786`). Smallest fix: make idle cancellation a successful empty outcome at the `SessionClient` boundary, preserving strict low-level `abort` if desired. Add slice regressions for idle reset and switch; do not weaken low-level assertions to conceal the mismatch.

**BUG B2 — Successful shutdown is rendered as an error containing the session ID.** Shared RPC shutdown returns `Some(session_id)` on success (`rpc_client.rs:181`); `SessionClient::shutdown` and `detach` pass that through (`session_client.rs:187`, `:196`). The slice interprets any returned string as an error and appends it (`slices/task_session_spawn.rs:375`). ACP returns only a close error, otherwise `None` (`client.rs:532`, `:560`). This occurs on successful RPC release that passes cancellation, and becomes more visible after B1 is fixed. Smallest fix: discard the RPC success ID in `SessionClient`, return `None` on successful teardown, and retain idempotent low-level teardown. Current enum tests assert the incorrect compatibility behavior (`session_client_tests.rs:230`; `session_client_claude_tests.rs:266`); add caller-level coverage and revise those contract expectations only with explicit test-change authorization.

**BUG B3 — A failed or exhausted SDK message iterator can leave a permanently busy, apparently healthy session.** `startPump` only logs iterator exceptions and resolves; normal exhaustion likewise emits nothing (`sidecar/claude_sdk_sidecar.mjs:177`). The sidecar remains initialized, its stdin listener remains live, and `handlePrompt` continues acknowledging prompts (`:232`, `:354`). With no `result`/EOF, the RPC client produces no terminal and `host_exited` remains false (`rpc_client.rs:109`, `:170`, `:193`; `rpc_session.rs:228`). ACP connection failure emits `Error` and `Exited` (`sdk_connection.rs:349`). Smallest fix: on unexpected iterator termination, send one defined failure signal and close the sidecar/query so the existing host-exit recovery can run; suppress it during intentional shutdown. Exact real-SDK timing is **UNVERIFIED**, but the missing terminal path is visible in code. Test both throwing and silently exhausted iterators; the current fake never exercises that sidecar failure (`fixtures/fake_claude_sdk.mjs:202`).

**BUG B4 — Claude error results finish as successful prompts.** A non-aborted `result` with `is_error: true` yields an `Error` event plus `finished=true` (`claude_sdk_map.rs:248`). `RpcSession` defers completion after those events (`rpc_session.rs:268`), then `RpcClientCore` unconditionally creates `RequestFinished { result: Ok({stopReason:"end_turn"}) }` for a non-aborted finish (`rpc_client.rs:138`). The drain classifies every `Ok` as `PromptTerminalOutcome::Success` (`slices/acp_drain.rs:18`, `:147`). An operator-visible error therefore accompanies a success terminal. ACP preserves the request’s `Err` (`sdk_connection.rs:765`). Smallest fix: preserve a failure outcome through the shared mapping/step boundary and deliver a failed `RequestFinished`, with a single operator error. `claude_sdk_map_tests.rs:354` only checks mapper flags and the error event; add a client-to-drain regression for `error_max_turns`.

**BUG B5 — Pi startup can lose child exit and report a dead session as healthy.** After receiving `get_state`, handshake consumes `JsonlRecord::Exited` and breaks successfully, degrading missing optional responses (`pi_rpc_handshake.rs:112`). It does not carry that exit into `RpcHandshake::pending` (`:172`). The later session sees a disconnected records channel as no next record (`rpc_session.rs:330`), and the core’s health check only consults its own exit flag/session presence (`rpc_client.rs:193`). ACP directly checks child status (`client.rs:563`). Smallest fix: fail startup if the process exits during discovery, or retain terminal transport state explicitly. Add a child that replies to `get_state` then exits before optional replies; existing degradation tests only send failed responses, not EOF (`pi_rpc_handshake_tests.rs:154`).

**BUG B6 — Pi handshake’s deadline is not enforced while records keep arriving.** Its timeout check is only in `TryRecvError::Empty`; unrelated records use `continue` (`pi_rpc_handshake.rs:81`, `:124`). A child emitting continuous non-handshake records without the required response can overrun the deadline and grow `pending` indefinitely. Claude checks its init deadline at the top of every iteration (`claude_sdk_client.rs:75`). Smallest fix: check the absolute deadline each iteration, retaining the existing state-required/optional-degrade policy. Keep a separate bound question for queued records; a 16 MiB per-record cap is not a total queue bound (`jsonl_process.rs:30`, `:72`). The adversarial control-flow case is clear; occurrence under ordinary Pi output is **UNVERIFIED**.

**BUG B7 — JSONL thread-start errors bypass child cleanup.** `JsonlProcess::spawn` spawns the child, then uses `?` on two reader-thread creations before constructing the owner with its `Drop` (`jsonl_process.rs:60`, `:73`, `:81`, `:87`). If a thread cannot start, the raw `std::process::Child` is dropped without the kill/wait implemented on `JsonlProcess`. Normal drop does kill/wait (`:167`); that guarantee does not cover these errors. Smallest fix: a local cleanup guard or explicit kill/wait before returning either thread-spawn error. This is an exceptional resource-exhaustion path; no runtime reproduction was attempted. ACP’s ordinary handshake failure explicitly kills/waits (`client.rs:459`, `:470`), although this audit does not certify every exceptional ACP allocation/thread path.

**BUG B8 — Pi current model selection loses provider identity.** `current_model_value` matches only `model.id`, and initial provider selection also finds by bare ID (`pi_rpc_client.rs:57`, `:131`). After selecting provider B’s `shared-id`, `applied_model()` uses B while `config_options()` can select provider A’s first `shared-id` (`:180`, `:211`, `:233`). This can persist/display the wrong provider because the slice saves from config options (`slices/task_session_spawn.rs:126`, `:135`). Smallest fix: carry and compare `(provider,id)` through discovery and current-value lookup. The supplied fixture has distinct IDs under one provider (`fixtures/fake_pi_rpc.js:137`), so the collision is untested; availability of such a catalog in the installed Pi environment is **UNVERIFIED**.

## Retain as-is

- **Shared RPC driver, provider mappers, and enum dispatch:** they have real distinct responsibilities and two consumers (`pi_rpc_client.rs:137`; `claude_sdk_client.rs:183`; `rpc_session.rs:259`; `session_client.rs:108`). Consolidating them wholesale is not the smallest fix for the identified bugs.
- **Deferred event-before-terminal delivery:** Claude usage/error events must precede finish (`rpc_session.rs:217`, `:268`; `rpc_session_mapper_tests.rs:101`). Change failure semantics without losing this ordering.
- **Fresh IDs and pending-record preservation:** required for mixed command replies and streamed events (`jsonl_process.rs:135`; `pi_rpc_handshake.rs:81`; `rpc_session_request_tests.rs:114`). Keep the interleaving tests even if happy-path tests are consolidated.
- **Bounded record framing and bounded stderr:** real transport failure defenses (`jsonl_process.rs:21`, `:27`, `:208`; `jsonl_process_bound_tests.rs:41`; `jsonl_process_tests.rs:290`). Per-line bounds do not justify claiming total queue bounds.
- **SDK resolution outside task-controlled npm configuration:** host runs global npm lookup from HOME and supplies a resolved module (`claude_sdk_spawn.rs:47`, `:99`); explicit/no-fallback tests protect the boundary (`claude_sidecar_resolution_tests.rs:99`; `claude_sidecar_override_tests.rs:138`). Keep direct/nested precedence fixtures; they are small and exercised.
- **Pi end-of-turn stats fallback and Claude zero-usage cancel suppression:** retain user-visible behavior while removing the synchronous-poll stall (`pi_rpc_client.rs:77`; `pi_rpc_client_usage_tests.rs:132`; `claude_sdk_map.rs:293`; `claude_sdk_map_tests.rs:230`).
- **Captured provider transcripts:** they exercise real wire shapes that the minimal fakes omit (`fixtures/claude_sdk/toolcall.jsonl:6`; `fixtures/pi_rpc/abort.jsonl:21`; `claude_sdk_map_tests.rs:168`; `pi_rpc_map_tests.rs:196`). Keep them alongside a small number of subprocess smoke tests.
- **Existing ownership boundaries:** the slice still owns prompt lifecycle and persistence; adapters return typed events (`slices/acp_drain.rs:62`; `slices/task_session_replacement.rs:50`; `session_client.rs:53`). Recommendations fix adapter contracts and do not move task truth into the sidecar or browser.
